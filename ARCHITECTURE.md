# Architecture

Lumen is one React Native (Expo) app for iOS and Android. Only the camera layer is native. Lumen uses
only the rear camera and flash.

## Data flow

1. **Capture (native).** `apps/mobile/modules/lumen-capture` runs the rear camera with the torch on,
   locks exposure, white balance, and focus, and reduces every frame to mean red, green, and blue
   over the finger region. Swift on iOS (AVFoundation), Kotlin on Android (CameraX). Frames never
   leave native code; batches of numbers are sent to JavaScript every 100 ms.
2. **Signal processing (`packages/core`).** Resampling, filtering, beat detection, beat classes
   (normal, atypical, artifact), heart rate, HRV, breathing rate, and the rhythm features. Pure
   TypeScript, so it runs identically in the app and in Node (`tools/replay`).
3. **Models (ONNX Runtime).** SQI-Net judges signal quality every second; Rhythm-Net classifies rhythm
   after the capture; diabetes-net checks the averaged pulse shape after a Full Scan. Each has a
   classical fallback, and each flag is gated by its evidence floor. The same `.onnx` files run in the app, in Node,
   and in Python.
4. **Decision rules and evidence.** Results are thresholded, then labeled from
   `docs/validation/evidence.json` (copied into the app). A result can never claim more than the
   evidence file supports.
5. **UI and storage.** expo-router screens in light and dark, Skia charts, SQLite for readings. Nothing
   is uploaded.
6. **Widgets and notifications.** After each saved reading the app writes a small widget snapshot (no
   condition names). iOS widgets and the standing-test Live Activity read it from an App Group;
   Android widgets read it from SharedPreferences. Reminders are local notifications with quiet hours
   and a daily cap; lock-screen text never shows health details.

## Testing without a camera

`ReplayCapture` implements the same interface as the native module using recorded captures, so the
whole app runs in emulators and CI. `tools/replay` runs the same pipeline in Node for validation.

## Quality gates

| Check | Script |
|---|---|
| Rear camera only | `scripts/scope-guard.mjs` |
| No network code in release paths | `scripts/priv-check.mjs` |
| Naming and silent-error rules for Python; comment heuristics | `scripts/check-style.mjs` |
| Commit message format | `scripts/check-commit-msg.mjs`, commitlint |
| WCAG AA contrast in both themes | `scripts/check-contrast.mjs` |
| No health details on the lock screen | `scripts/check-notification-copy.mjs` |
| Diabetes wording | `scripts/check-diabetes-copy.mjs` |
| Brand kit and icon assets | `scripts/check-logo.mjs`, `scripts/check-assets.mjs` |
| Milestone acceptance | `scripts/proof/` |

## Conventions

- `ios/` and `android/` are generated by `expo prebuild` and never committed.
- Every tunable value lives in `packages/core/src/config.ts` (mirrored in `dsp_config.json`).
- Comments explain *why*, not *what*. No generic names (`data`, `result`, `handleX`), no empty catch
  blocks, no unused code.
